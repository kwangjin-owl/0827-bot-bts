상세 — 일곱 레인 · 화살표 오십

  
Agent Logic 레인을 따로 세우고 슬롯 정의 적재 단계를 넣었습니다.

  
sequenceDiagram
    autonumber
    actor U as 손님
    participant F as 폼 UI<br/>FORM_STATE
    participant B as 챗봇 UI<br/>BOT_STATE
    participant L as Agent Logic<br/>슬롯 판단
    participant M as Memory<br/>history 2턴 창
    participant C as Context<br/>장소사전 218곳 · slots.json
    participant S as 백스테이지<br/>배차 · Supabase

    Note over U,S: [단계 0] 슬롯 정의 적재 - settings.py → make_config.py → slots.json
    C->>F: 묻는 칸 목록 제공(갈래별 8~9칸)
    C->>B: 묻는 칸 목록/질문 문구 제공(ASK_STYLE=one_by_one)

    Note over U,S: [단계 1] 장소 접수 - 같은 아홉 칸을 두 방식으로
    alt 폼으로 예약(아홉 칸이 한 화면)
        U->>F: 갈래 선택(관광/숙소/식당)
        F->>C: 갈래별 칸 구성 요청
        C-->>F: 칸 재구성 반영(관광 8칸, 숙소/식당 9칸)
        U->>F: 조건 입력(종류/지역/가격대/옵션)
        F->>C: 후보 조회(조건 AND 결합)
        C-->>F: 후보 목록 제공(헬스장 ON 시 71곳 → 19곳)
        U->>F: 장소 선택
        C-->>F: 주소/연락처/평점 자동 반영(AUTO_SLOTS)
    else 챗봇으로 예약(한 칸씩 주고받기)
        U->>B: 자연어 발화(예 - 헬스장 있는 숙소요)
        B->>L: 발화 전달
        L->>M: 최근 2턴 조회(history_turns=2)
        M-->>L: 창 안 발화만 반환(3턴째부터 앞이 밀림)
        L->>L: Gemini 추출 요청(api/extract.js) - 실패 시 규칙 대체
        L->>C: 장소사전 대조(갈래/종류/지역 보강)
        C-->>L: 정규화 값 반환(창과 무관하게 항상 조회 가능)
        L->>M: 이번 턴 기록
        L-->>B: 부족한 칸 1개 질문 생성
        B->>U: 들은 값 되짚기 + 한 칸 질문
    end
    Note over M,C: Memory는 밀린다(요약판에 잊음 표시) · Context는 안 밀린다(참조)

    Note over U,S: [단계 2] 두 도메인이 이어지는 단 하나의 자리 - 장소 이름 → 택시 칸
    Note over L,C: 실데이터 - 출발지 47 / 도착지 24 / 연결 안 함 29 → 자동 이월 금지
    alt 폼
        U->>F: 장소와 같게 체크(타는 곳 또는 내리는 곳)
        F->>F: 이월 칸 고정(장소 변경 시 연동 반영)
    else 챗봇
        L-->>B: 이월 질문 생성(어느 칸에 넣을지)
        B->>U: 1회 확인(호텔 파크에서 타세요, 아니면 호텔 파크로 가세요)
        U->>B: 응답
        B->>L: 응답 전달
        L->>L: 타는 곳/내리는 곳 확정(carry 처리)
        L->>L: 장소 변경 시 옛 이름 잔존 검사 후 재확인
    end

    Note over U,S: [단계 3] 택시 연계 배차 및 데이터 갱신 프로세스
    U->>F: 출발지/시간/택시 종류 입력 및 배차 요청
    U->>B: 남은 칸 응답 및 배차 요청
    F->>S: 배차 요청 접수(폼 경로)
    B->>S: 배차 요청 접수(챗봇 경로)
    rect rgb(238, 242, 250)
        Note over S: [백스테이지 핵심 처리]
        S->>S: 기사 배정 및 연락처 자동 발급(AUTO_SLOTS)
        S->>S: 슈퍼베이스 저장/갱신(booking - 폼·챗봇 공용 표)
        S->>S: 변경 이력 기록(booking_change - 연쇄 여부 표시)
        S->>S: 웹/폼 반영 및 봇 대화 흐름 업데이트
    end
    S-->>U: 예약 완료 통보(예약번호 TX-0007 / 경로 / 기사 연락처)
    Note over F,B: 작성 중인 값은 FORM_STATE와 BOT_STATE로 분리 - 저장되는 표는 하나
  

  
Memory는 3턴째부터 앞을 놓치지만 Context는 창과 무관하게 남는다. 밀려난 칸을 되찾는 것도, 저장하는 것도 Context 쪽이다. 작성 중인 값만 폼과 봇이 따로 쥐고, 저장되는 표는 하나다.
